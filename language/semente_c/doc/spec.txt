SPEC FORJA - forja 0.23.0 (Linguagem v1.13). Referencia compacta por TEMA (estado real do compilador); receitas e exemplos: cartao.txt; codigo -> secao: mapa_spec.tsv.
Marcas de bloco ```fj: ver cartao.txt. Um jeito so, tudo explicito (tipo, alocador, erro, unidade); sem macro, sobrecarga, metodo, conversao implicita, heranca, excecao, GC, `;` nem truthiness.

== formato ==
`.fj` UTF-8; modulo = 1 arquivo; a raiz tem `proc main()` (sem parametros e sem valor; `-> ! E` vale). Nomes ASCII `a-z A-Z 0-9 _`; tipo, unidade, struct, enum PascalCase; constante MAIUSCULO; resto snake_case (E0102; nome de proc foreign e o do C). Comentario `//`. Forma de outra linguagem (`;` `&&` `||` `!x` `i++` `a ^ b` `c ? a : b` `x?` `fn` `:=` `elif`, comentario de bloco, `try {} catch`, `main -> int`, corpo na linha do `{`) e E0110, nunca aceita: a causa diz a forma da Forja (`and or not`, `+= 1`, `if`/`else`, `try x`, `proc`, `let`, `else if`, `//`, `switch`, `os.exit(n)`) e `correcao` traz a troca quando e mecanica. Nome antigo renomeado (`em =`, `escopo`, `para =`, `std:arquivo`, `vendor:banco`...) tambem e E0110 "forma antiga; rode forja migrar". Corpo de `if for while switch proc test` e de struct em linhas proprias depois de `{`. Reservadas: const let var proc struct enum union unit pub export import as foreign test if else for in while switch case default break continue return defer try or_else and or not true false none. Embutidos reservados: print expect assert panic new make delete len append insert get get_ptr has remove frame_reset format format_c transmute slice_from size_of align_of offset_of static_assert sqrt min max clamp abs transpose conj main link dynamic map bit_set soa matrix quat e os nomes de tipo. Literais: `12 0xFF 0b101 1.5 "txt" f"..." true false none`.

== declarar ==
`const N: i32 = 9` (tipo obrigatorio); `let x = e` imutavel; `var x: T = e` mutavel; so `var` recebe `=`, `+=`, `-=` (nao ha `*=` `/=`; E0705). `var` sem alteracao E0707; local sem leitura E0708 (`_nome` isenta); retorno descartado E0709 (`_ = f()`). Local infere: inteiro puro `int`, real puro `f32`; literal inteiro exato vira real no contexto real.
Tipos: `i8 i16 i32 i64 u8 u16 u32 u64`, `int uint` (64 bits), `f32 f64`, `bool`, `str` (bytes UTF-8 imutaveis), `cstr` (`char*` com NUL, so para C), `rawptr`; `c_long`/`c_ulong` = `long` do C: 32 bits no Windows, 64 no Linux; so na fronteira com C. `^T` nunca nulo; `?T` valor ou `none`; `?^T` ponteiro anulavel; `?cstr`. Derivados: `[N]T []T [dynamic]T [dynamic, N]T map[K]V bit_set[E] soa[N]S matrix[R, C]T quat T ! E`.
Operadores: `+ - * / %`, `== != < <= > >=`, `and or not`, `& | ~ << >>` so em sem sinal (E0303): `a ~ b` e o xor (binario) e `~a` unario e o not bit a bit; `a ^ b` e E0110 (correcao `^` -> `~`; `p^.campo`, `p^[i]` e `p^ + 1` seguem sendo deref, `x^` sozinho e E0306). Precedencia estilo Go: `* / % & << >>` pesam mais que `+ - | ~`, que pesam mais que a comparacao; so existem `+=` e `-=` (nao ha `|=`, `&=`, `~=`, `<<=`). `-x` nao em sem sinal (E0305). Inteiro nunca tem comportamento indefinido: `x / 0` e `x % 0` valem 0, deslocar por largura ou mais vale 0, e o estouro da a volta em release (`MIN / -1` e R0002 em dev, volta em release). Sem mistura de tipos (`int + i32` E0301): `as` entre numericos, ponteiros (`n as ^T` checa nulo, R0005) e `cstr as str`; `transmute(x, to = T)` reinterpreta bits (mesmo tamanho). Estouro de inteiro e faixa travam em dev/test (R0001, R0002), nao em release (a volta e definida, sem UB).
Ponteiro: `&x` (x `var`), `p^`, `p.campo` (um nivel); sem aritmetica (E0306). Unidade: `unit Metros: f32`, `unit Vel = Metros/Segundos`; `+ - == <` so na mesma unidade, `* /` combinam (E0412), troca so por `as`; some no C. Faixa: `vida: i32 in 0..=100 = 100` (R0001; constante fora = E0420). Layout: `size_of(T) align_of(T) offset_of(T.campo)` (int constante), `static_assert(cond, msg = "...")` (E0328, E0329).
```fj
proc main() {
    let a: i32 = 7
    var n = 0
    n += a as int
    print(n % 4)
}
```

== proc ==
`proc nome(a: T, b: U = padrao) -> R { }`; retorno de valor termina em `return` (E0302). Chamada: cada argumento e posicional (na ordem dos parametros) OU `nome = valor` (na ordem declarada); posicional depois de nomeado E0502, nome fora de ordem E0501; faltar obrigatorio E0503, nome inexistente E0504; os com padrao podem faltar. Parametro e imutavel: para alterar receba `^T`. Retorno multiplo nomeado 2..8: `-> (q: int, r: int)`, `return a, b`, `let q, _ = f()`; tupla nao e valor (E0314). `pub export proc` gera simbolo C sem prefixo, so tipos de fronteira (E0901); `struct` literal `Tipo{campo = valor}`; campo omitido vale o padrao ou zero; `^T` exige padrao.

== fluxo ==
`if c { } else if c { } else { }`, `for i in a..<b`, `a..=b`, `for x in lista`, `for &x in lista` (referencia), `for i, x in lista`, `while c`, `break continue` (E0701), `return`, `defer chamada` (fim do bloco, ordem inversa; E0702). `switch v { case A: }` sem fallthrough cobre tudo ou tem `default` (E0607, E0608); enum sempre `Enum.membro`; `enum E { a = 1, b }` aceita valor (i32). `union U { A, i32 }`: 2..255 variantes, sem valor zero nem `==` (E0313), `let u: U = 9 as i32`, `switch c in u { case A: }`.

== erro ==
`T ! E` valor ou erro (E enum, E0605, E0609); `! E` so erro. `try x` repassa (proc `! E` do mesmo E; E0602, E0603), `x or_else v` padrao (E0604), `switch r in x { case T: case E: }`; ignorar `T ! E` = E0601. `?T`: `none`, `x or_else v`, `x == none`, `switch v in x { case T: case none: }`; sem `try`, sem `??T` (E0312). `assert(cond, msg = "txt")` (msg cstr) vale em qualquer lugar, falso = R0003 (exit 101, tambem em release); `panic("txt")` idem; `expect(cond)` so em `test` (E0801). `main -> ! E` devolvendo erro: R0004, exit 1.

== memoria ==
`new(T, alloc = X)` -> `^T`; `make([dynamic]T, alloc = X, cap = n)`; `append(&l, item = v)` recebe o ENDERECO; `delete(x)`; `frame_reset()`. `X` = `heap | frame | scope | <Arena> | <Pool>`. heap: um dono, `delete`/`defer delete` ou entrega (E0317), vazamento no fim do `run` dev = R0009; frame: 16 MiB ate `frame_reset()`; scope: solta no fim do bloco, so `let`/`var`, nao sai (E0316). Arena/Pool: `std:mem`. `[dynamic]T`, `map`, `soa[dynamic]` sao donos, nao se copiam (E0311): `&l` altera, `l[..]` empresta, `return local` move. Resultado de `new`/`make` guardado (E0310). `delete(p)` de NOME (`^T`, `?^T`, `cstr`) zera o nome (dev e release): delete duplo pelo mesmo nome e no-op, uso depois e R0005; lista/map/soa seguem como estao; `delete(c.p)`/`delete(l[i])` nao zeram. Impossivel alocar R0007; uso errado (delete duplo por ponteiro guardado em estrutura ou liberado em outro proc, frame velho) R0008 so dev. Rastreio de `std:mem`: `MemSnapshot`/`snapshot`/`report_since`, e `track_handle(kind, h)`/`untrack_handle(h)` para handle de lib C (em release a chamada some, mas os argumentos ainda sao calculados: sem efeito colateral neles). Endereco de local nao sai do proc (E0706). Ponteiro para dentro de lista/map (`&l[i]`, `l[..]`, `get_ptr(&m, ...)`) nao vale depois que a MESMA colecao muda pelo mesmo nome (`append`, `insert`, `remove`, `delete`, `clear`, `resize`: o buffer pode mover): lido depois da mutacao, usado num laco que muta, ou colecao mutada dentro de `for &x in l` = E0913; guarde o indice ou pegue o ponteiro de novo (`p = &l[0]` revalida); entre procs vale a guarda de memoria. Alias: `^T` e fatias do mesmo buffer podem se sobrepor (o compilador nao as trata como `restrict`); donos distintos (lista, map, soa, `str` dona) NUNCA compartilham buffer.

== colecoes ==
`[N]T` valor (N literal ou const; literal `{a, b}` com N exato e tipo pelo contexto, `{}` zero; E0308, E0309); fatia `[]T` visao (`a[..]`, `a[lo..<hi]`); indice fora R0006 (no release `--checagem nao` o tira), constante fora E0421; `len`. Em `[N]T` numerico: `a + b`, `k * a` por elemento (E0331); swizzle `v.xy`, `c.bgra` em `[2..4]T` (E0332). `[dynamic, N]T` valor com capacidade fixa (`{}`, `append`, cheia R0007; E0335). `map[K]V`: `insert(&m, key = k, value = v)`, `get(m, key = k)` -> `?V`, `get_ptr`, `has`, `remove`, `len`; ordem de insercao; E0318. `bit_set[E]` ate 64 membros, `| & -` (E0319). `soa[N]S`, `soa[dynamic]S`: `a[i].campo`, `a.campo` fatia, `&a[i]` E0320. `matrix[R, C]T` 2..4, f32/f64, `m * m`, `m * v`, `transpose` (E0321). `quat{x,y,z,w: f32}`, `q * r`, `conj` (E0333).
Embutidos de colecao (`l` = lista var, `&l`; `s` = fatia `l[..]`, array ou fatia; elemento dono so entra em append/insert_at, E0311): lista `cap clear reserve resize truncate pop insert_at ordered_remove unordered_remove remove_value dedup` (`pop` -> `?T`; indice fora R0006); busca `index_of last_index_of contains count` (`value =`), `index_by find_by any_by all_by count_by` (`pred = proc(^T) -> bool`), `min_of max_of sum avg`; mexer `copy fill swap reverse replace_value clone`; ordem `sort`, `sort_by(less = p)`, `sort_by_key(key = S.campo)`, `binary_search` -> `(int, bool)`; sorteio `shuffle choice` (`rng = &r` de std:rand, E0338); fila de prioridade `heap_push heap_pop heap_push_by heap_pop_by`; map `keys values clear`; conjunto `map[K]bool`: `set_union set_intersect set_diff`. Inteiros (2 do mesmo tipo, E0334): `wrapping_add wrapping_sub wrapping_mul` (volta), `saturating_*` (trava), `checked_*` (`?T`), `overflowing_*` (par `valor, estourou`), `rotate_left rotate_right count_ones leading_zeros trailing_zeros byte_swap mul_hi_u64` (`count_ones`, `leading_zeros` e `trailing_zeros` devolvem `int`). Texto: builder = `[dynamic]u8` (`append(&buf, item = "txt")`, `format(f"...", into = &buf)`, `to_str(&buf)` move os bytes para `str` SEM copia quando o builder tem capacidade sobrando (cap > len); com cap == len cresce 1 byte para por o NUL e isso copia (sonda G3 9e). `from_bytes`, `as_bytes`. `map[str]` NAO copia a chave: a chave vive em `mem.Arena` (ou lista dona) ate o ultimo uso do mapa; `delete(k)` logo depois do insert = acesso invalido, sem R-code (contorno: chave em arena).

== texto ==
`str`: `len` em bytes, `==`; sem `+`, sem indice (E0308). `"..."` nunca interpola. `f"vida {v} {x:08.3}"`: `{expr:[0][largura][.prec][x]}`, `{{ }}`, so como 1o argumento de `print`, `format`, `format_c` (E0315). `format(f"..", alloc = heap|frame)` -> `str`; `format_c` -> `cstr`. `print` aceita inteiro, real, bool, str, cstr. Real sem precisao (`print(x)`, `f"{x}"`) mostra o MENOR texto que volta ao mesmo valor, sempre posicional (sem expoente: 1e300 sai com 301 caracteres), sem `.0` sobrando (`3.0` sai `3`), `nan inf -inf -0`; `{x:.N}` (N 0..30) e exato; igual no backend C e no nativo. `cstr as str` empresta; `str` -> `cstr` so por `format_c` (E0307). `text.parse_float(s) -> f64 ! ParseError` (std:text, 0.23.0): arredonda certo (meio para o par, subnormais, underflow vira 0.0; acima do maior finito = `ParseError.overflow`), igual ao `float()` do Python.

== foreign ==
`foreign { link "lib"  proc nome(a: T) -> R [clausula] }` com clausula de posse opcional (no maximo uma, E0912): `creates` (o retorno e o handle novo), `creates p` (parametro de saida `^H`), `destroys p`, `takes p`, `ends` (sem parametro: o proc encerra a lib inteira, e a memoria que ela guarda de proposito ate la nao e vazamento, ex.: `link "sqlite3"` + `proc sqlite3_shutdown() -> i32 ends`; `ends p` = E0912), p = parametro de tipo `^T`/`?^T`/rawptr/inteiro/struct (ex.: `proc fclose(f: ?^File) -> i32 destroys f`); nome = simbolo C (alias `proc nome = "simbolo"(..)`); `link` opcional; `pub foreign`; o mesmo simbolo C pode ser declarado em varios modulos so com parametros e retorno identicos (senao E0202). Tipos que atravessam: inteiros, reais, `bool`, `^T`, `?^T`, `cstr`, `?cstr`, `rawptr`, enum, struct por valor, `quat`, `opaque N` (so atras de ponteiro, E0908), callback `proc(..) -> R` so como parametro (E0907, E0909..E0911); nao: `str`, listas, map, soa, matrix (E0904). `slice_from(p, len = n)` -> `[]T` emprestada. `cstr`/`^T` de C e emprestado (sem `delete`). `pub export proc` em DLL: `build --modo dll` exporta `forja_dll_info` (funcao sem parametros que devolve struct de 32 bytes: magic 0x494A4446, formato 1, hash FNV-1a 64 do texto canonico da interface, ponteiro e len do texto; o texto lista os procs `pub export` em ordem de nome e os tipos alcancados com campos/offsets, membros/valores de enum, opaque; o hash muda com campo acrescentado, ordem ou tipo trocados, membro de enum novo, export acrescentado ou removido, e NAO muda com corpo, constante ou nome de parametro; `--debug-code interface` escreve `## interface` no .debug.txt); `forja ligar` gera o bloco (`--propor`, por arquivo, grava `creates`/`destroys` nos procs de nome open/create/close/free etc., com o comentario `// proposto por forja ligar --propor: confira`; `takes` entra a mao).
Hot reload (`std:reload`, so Windows; no Linux todo proc devolve unsupported_target): `open(path, alloc)` carrega uma COPIA sombra `.forja_quente\<nome>_<pid>_<n>.dll` ao lado da DLL (a original pode ser regravada); `reload(lib) -> ?ReloadError` troca so se o hash de `forja_dll_info` da DLL nova for IGUAL (senao interface_changed e a velha segue, e DLL sem o export esperado tambem: o hash cobre os nomes); sucesso sobe `generation(lib)` e descarrega a velha.
Contrato do host: rebusque `symbol` quando `generation` muda (o ponteiro velho morre); `group_wait` de todo grupo (std:async) que roda codigo da DLL ANTES do reload; globais da DLL recomecam na troca, entao o estado mora no host, num `^Estado` POD sem ponteiro para memoria da DLL; `close` em todo `open` (Library aberta sem close = R0009 em dev, no fim do host). Exemplo: exemplos_libs\hot_reload\ (host.fj, jogo.fj, LEIAME.txt).

== testes ==

Opcoes de ferramenta (nao mudam a linguagem): `build|run|test --perfil` (exe, dev ou `--release`; Windows e Linux; com `--modo dll` ou `--suporte` = exit 2) grava `<exe>.perfil.json` (Chrome Trace, abre no Perfetto; teto 1.048.576 eventos, campo `truncado`) e `<exe>.perfil.txt` (agregado por proc: chamadas/total/proprio/%proprio/nome; o que a IA le); `FORJA_PERFIL_SAIDA=<base sem extensao>` troca o caminho; procs inlinadas nao aparecem em release (`--sem-otim inline` mostra); recursiva: total conta so a chamada mais externa; `os.exit` e panic gravam os 2 arquivos; R0009 em dev NAO grava o perfil; `run --perfil` sem FORJA_PERFIL_SAIDA deixa o arquivo no exe temporario (use `build` ou a variavel); `--debug-code perfil` lista as procs instrumentadas; custo ~9-10x: serve para achar o gargalo, nao para tempo absoluto.`check --canonico` (F0001 se o arquivo foge da forma canonica); `--tempos <t.json>` grava os tempos por etapa; `build --debug-code <lista>` (itens: bir, asm, quadros, reloc, formato, tempos, json, locais, linhas, otim, interface, perfil, passes; `ir` = X0003; `passes` (0.23.0) = `== entrada` e `== passe <nome>` com a BIR inteira depois de cada passe, so texto, pedido pelo nome: nao vem com `,json`), `--prova-layout`, `--entradas <arq>` e `--lib-pasta <pasta>` (so backend x64); `--simbolos sim|nao` (DWARF; padrao sim em dev, nao em release); `--traco` (o programa escreve o traco do diferencial em stderr); `--guarda-memoria` (dev, x64, exe); `--sem-otim <passo[,passo]|tudo>` (build, run e test, so release; desliga passes de otimizacao do x64; `--debug-code otim` lista os contadores); `--pie` (so `--target x86_64-linux`); `build --projeto [forja.proj] [--plano] [--tudo] [--jobs N]` (N de 1 a 64).
Alvo Linux: `build --target x86_64-linux a.fj -o a` gera ELF estatico sem libc (dev e `--release`; o x64 e implicito); `run` nao executa ELF (X0003: compile e rode no Linux); `test --target x86_64-linux -o t a.fj|std:m` so constroi o exe de teste; `foreign` com biblioteca e `--modo dll` no Linux = X0003. No PowerShell 5.1 chame o forja pelo Bash ou por `subprocess` do Python (ele estraga aspas e argumento vazio).
`run` e `test` aceitam `--limite-tempo <seg>` (R0013, exit 102), `--limite-mem <MiB>` (R0014, exit 103) e `--limite-saida <bytes|KiB|MiB>` (R0015, exit 104; a saida e cortada no limite); `run --args-file <arq>` = um argumento por linha, UTF-8 (`\n` e `\\` escapam). Erro de execucao = JSON no stderr com `explicacao`, `forma_certa` e `spec`.
`build|run|test --rastreio` (no backend x64 em dev, Windows e Linux, e o padrao e a flag e redundante; no backend c e opt-in, com a mesma linha JSON; o `--release` ignora; `check`/`ast`/`--suporte` = exit 2) acrescenta ao R-code `coluna` (se o quadro de cima esta na linha do erro), `valor` (R0006 `{"indice","tamanho"}`; fatia `{"inicio","fim","tamanho"}`) e `pilha` = `[{"proc","arquivo","linha","coluna"}]` do mais fundo ao main (ate 8; `quadros` = total se passar). No backend c, sem a flag o exe e o R-code ficam identicos; no x64 dev o exe sempre leva a tabela de posicoes.
`ast [--tipos] [--sem-pos] [--no ID] [--projeto] a.fj|pasta` = AST 1.0.0 em JSON: todo no tem `id` estrutural (`modulo:decl/corpo[2]/valor`, estavel se outro ponto do arquivo muda), `pos` e `fim` [linha, coluna] (fim exclusivo: editar = trocar o texto entre os dois e reparsear) e, em uso de nome, `ref` (id da declaracao), `ref_modulo` e `ref_tipo` (`embutido` = so este, sem `ref`); `--sem-pos` tira posicoes; `--no ID` so a subarvore; `--projeto` ou pasta com `main.fj` = um item por modulo, imports primeiro e raiz por ultimo.
`consultar simbolos|escopo|refs|tipo|assinatura|campos <argumento> [a.fj|pasta] [--modulo <caminho>] [--json]` = pergunta ao indice semantico do projeto (uma analise; so compila sem erro): `simbolos` (declaracoes, categoria, entrada main/export), `escopo arq:L:C`, `refs <nome | Tipo.campo | Enum.membro | proc.param>` (usos nas mesmas posicoes do `ref` do `ast`), `tipo arq:L:C`, `assinatura <proc>`, `campos <Tipo>`, `callers <proc>` (cada chamada: quem e onde), `callees <proc|test>` (o que chama, com contagem; embutido = categoria `embutido`), `imports` (grafo de modulos, apelidos e `link` de foreign), `api <modulo>` (pub com assinatura e o comentario `//` colado acima), `testes`, `entrada` (main e `pub export`); sempre 1 linha de JSON estavel; exit 0 ok, 1 projeto com erro (diagnostico do check), 2 uso (pergunta ou nome inexistente), 3 interno.
`mapa [a.fj|pasta] [--json | --resumo] [--modulo <caminho>] [--limite N]` = visao geral do projeto (mesma compilacao do `consultar`): `--json` = tamanho, entrada, modulos, api (as linhas de `consultar api`), tipos (struct com campos, enum com membros, union com variantes), testes e dependencias; `--resumo` (padrao) = texto curto: modulos, tipos e nomes pub (`+K` = cortados por `--limite`); `--modulo X` = so o modulo X, com assinaturas e campos; saida deterministica.
`editar [a.fj|pasta] --ops ops.json [--aplicar]` = edicao estrutural do projeto: `ops.json` e uma lista de `{"op":"renomear","id":<nome | Tipo.campo | Enum.membro | proc.param | id>,"novo":<nome>}` (declaracao e todos os usos, entre modulos; texto de string e comentario nao mudam), `{"op":"trocar_no","id":<id do ast>,"texto":<expressao ou comando>}`, `{"op":"trocar_corpo","id":<proc ou test>,"texto":<corpo>}`, `{"op":"inserir_decl","texto":<declaracao>,` + UMA posicao: `"depois_de"`/`"antes_de":<id de declaracao>`, ou `"modulo"` (ou `"arquivo"`) com `"no_fim":true` / `"no_inicio_depois_dos_imports":true`}, `{"op":"remover_decl","id":<declaracao>[,"forcar":true]}` (leva o comentario colado e os imports que so ela usava; recusa, sem desfazer, se ainda ha referencia, a menos que `forcar` deixe o check decidir) e `{"op":"mover_decl","id":<declaracao>,"para":<modulo>}` (vai para o fim do destino; imports e chamadas dos modulos tocados sao ajustados, `pub` entra quando outro modulo passa a usar; ciclo de import, `main` e raiz importada sao recusados). Sem `--aplicar` = so a resposta JSON (`edicoes` com linha, coluna, antigo e novo; `diff`; `erros_antes` e `erros_depois` do check; `valido`), nada gravado. A edicao que deixaria mais erros ou um erro diferente e DESFEITA (exit 1, `desfeito` true, `diagnosticos` = o pacote do check, 0 arquivo alterado); idem colisao de nome (E0202). Exit 0 ok, 1 desfeita ou recusada, 2 uso, 3 interno.
`migrar <a.fj|pasta>... [--dry-run | --aplicar] [--comentarios]` = troca os nomes antigos da tabela de renomeados pelos novos (analise semantica, nunca regex; import e qualificador andam juntos; 1 linha por troca no JSON; so ha mudanca de texto dentro da linha; a 2a passada acha 0 trocas); `--comentarios` tambem reescreve o codigo Forja que parseia dentro de comentarios `//` (prosa e texto misto nao sao editados: vao para o estado `revisao_comentario` com linha, coluna, trecho e formas antigas); sem `--aplicar` nada e gravado; exit 0 rodou, 1 ha arquivo `nao_analisado` (tem erro: nao e editado), 2 uso.
Campo `relacionados` do diagnostico (E0201 E0202 E0301 E0310 E0311 E0502 E0503 E0504 E0607 E1003): lista de ate 5 objetos {papel, arquivo, linha, coluna, texto, nota} com o que resolve o erro sem abrir o arquivo; `texto` = a linha do fonte do relacionado (ate 120 bytes, sem indentacao), `nota` = por que ele importa. `papel`: `declaracao` (let/var/parametro/const/campo do nome), `tipo` (struct, enum ou union, com os campos ou membros na nota), `assinatura` (o proc chamado com nomes e tipos dos parametros, o local de tipo proc, ou o proc que contem o erro), `parecido` (candidato do "voce quis dizer", o 1o e o mais perto), `uso_anterior` (a 1a ocorrencia do nome repetido). Sem relacionado especifico vale a declaracao que contem o erro; nos outros codigos a lista e `[]` (ou o campo nem sai, no diagnostico sem correcao).
Todos os erros numa execucao: `check` mostra os erros do programa ate `--max-erros N` (1 a 100; padrao 20), um por linha, na ordem do fonte (a raiz sempre vem antes do que depende dela). Lexico, sintaxe e semantica nao se misturam: erro de uma fase esconde a fase seguinte ate ser corrigido. O parser re-sincroniza no fim da linha (e do bloco que ela abre) ou na proxima declaracao de topo; a semantica segue no comando seguinte do mesmo corpo.
Erro em cascata (nome sem declaracao, tipo ou valor invalido) e SUPRIMIDO, nunca ligado: o nome sem declaracao e relatado uma vez por corpo; `let`/`var` que falhou deixa o nome com o tipo escrito (ou invalido) e os usos dele nao geram erro; declaracao com erro (struct, enum, const, proc) nao gera erro em quem a usa. Corrigido o erro raiz, a cascata reaparece se era erro de verdade.
